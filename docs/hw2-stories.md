3. **Given** the factorial specification and the `factorial(n) >= 1` proof

   **Then** the proof completes successfully
   **And** if not using `nonlinear_arith`, the proof uses `vstd::arithmetic::mul::lemma_mul_inequality` directly after the recursive call

4. **Given** the monotonic lemma for factorial
   **When** I write a recursive implementation of `factorial` that returns the same value as the specification

5. **Given** the recursive implementation and monotonic lemma
   **When** I write an iterative implementation of `factorial` that returns the same value as the specification
   **Then** the implementation verifies when `factorial(n as nat) <= usize::MAX`
   **And** the loop invariant properly bounds the iteration variable
   **And** the monotonic lemma is used in the verification

### Dev Notes

- Follow the pattern from Chapter 4 triangle example
- **Proof Mode:** Most proofs can be completed with `nonlinear_arith` mode: `proof fn f(..) by (nonlinear_arith)`
- Control flow in proofs should follow control flow of specification
- Use `assume(false)` to develop proof path by path
- Use `assert` to identify where Verus is stuck, then apply lemmas
- Can write normal `#[test]` functions and use `cargo test` to verify implementations before attempting proofs
- The rewrite engine in Verus is effective once it has necessary lemmas

4. **Given** the sum_to_n specification and monotonic lemma

## Story 3: Implement GCD Specification and Proofs

**Status:** drafted

### Story

As a **Verus learner**,
I want to **implement gcd specification and prove key properties about it**,
so that **I can work with more complex mathematical proofs that require specialized lemmas**.

### Acceptance Criteria

1. **Given** the pattern from previous problems
   **When** I write a recursive specification for `gcd(a: nat, b: nat)`
   **Then** the specification follows the same pattern
   **And** the specification is verified by Verus

2. **Given** the gcd specification
   **When** I prove `lemma_gcd_positive(a: nat, b: nat)` with requires `!(a == 0 && b == 0)`
   **Then** the proof ensures `0 < gcd(a, b)`
   **And** the proof completes successfully

   **When** I prove `lemma_gcd_divides(a: nat, b: nat)` with requires `!(a == 0 && b == 0)`

   **And** the proof uses:

   - `lemma_gcd_positive`
   - `vstd::arithmetic::div_mod::lemma_fundamental_div_mod`
   - `vstd::arithmetic::div_mod::lemma_mod_adds`
   - `lemma_mod_mul_zero` (provided in homework)
     **And** the proof completes successfully (nonlinear_arith mode is not enough)

4. **Given** the gcd specification and lemmas
   **When** I write recursive and iterative implementations
   **Then** both implementations verify
   **And** the iterative version has a proper loop invariant (the tricky part)
   **And** both implementations are trivial to prove with the lemmas

### Dev Notes

- GCD proofs require more specialized lemmas than previous problems
- The `lemma_gcd_divides` proof is the most complex - `nonlinear_arith` mode alone is not sufficient (unlike other problems)
- Must implement `lemma_mod_mul_zero` first (Task 3) as it's a prerequisite for `lemma_gcd_divides`
- The iterative implementation's loop invariant is the tricky part, not the proof itself
- **Loop Invariant Guidance:** Loop invariants must relate to the post-condition in the `ensures` clause, otherwise they are useless. The `invariant` is all that Verus knows about what the loop does when proving the post-condition. (See Section 5.3 from homework notes)
- See Section 11.2 for information about integers and nonlinear arithmetic
